# One Host Dispatcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every external call from a context-guru core package goes through a host-provided `dispatch.Dispatcher`; no core package creates an HTTP client, reads an API key or holds a credential.

**Architecture:** A new core package `dispatch` defines `Request`, `Response`, `Ref` and the `Dispatcher` interface (`Do`, `Release`, `Price`). The core builds wire bodies and parses responses; the host resolves an opaque `Ref` to a base URL and credential and sends. The proxy gets one `Dispatcher` for pings and cheap-model calls; Cortex gets its own.

**Tech Stack:** Go 1.26 (module `github.com/rossoctl/context-guru`), `net/http`, `gjson`/`sjson`, bifrost schemas.

**Spec:** `docs/superpowers/specs/2026-10-13-dispatch-design.md` (engine repo).

## Global Constraints

- No core package uses `http.Client`, `http.DefaultClient`, `http.Get`, `http.Post`, `http.NewRequest*`, or `os.Getenv` for a key. Host allow-list: `proxy/`, `proxyapp/`, `dash/`, `cmd/`, `examples/`, `internal/modelinfo/litellm/`, `dispatch/dispatchtest/`.
- Response bodies are bounded at `dispatch.MaxResponseBytes = 1 << 20`.
- A host never follows a redirect, and returns `dispatch.ErrNotHeld` (sending nothing) for an unknown or released `Ref`.
- The proxy's behavior does not change, except: (a) the component `model:` block rejects `provider`, `base_url`, `api_key`, `auth`; (b) the proxy's pings and cheap-model calls no longer follow redirects.
- Commits: `git commit -s`, conventional title, trailer `Assisted-By: Claude (Anthropic AI) <noreply@anthropic.com>`. Never `Co-Authored-By`.
- Go is available locally (`go` 1.27). `./proxy/...` with `-race` takes about 7.5 minutes: use a 600 s timeout and run it alone.

## Spec amendments (found while planning; applied to the spec in Task 1)

1. **Per-request `Ref`s are not dropped at request end.** Async work keeps the model after the request: the detached summary (`components/offload/cache_aware_async.go:154`) and the keep-alive summary candidate. The proxy deduplicates incoming refs by (base URL, credential) and expires one after `IncomingRefTTL = 2h` without use. Today the key lives unmasked in the `cheapmodel` struct for as long as anything holds it, so this is stricter than today.
2. **Ping usage parsing.** A small parser for non-streaming ping responses, `keepalive.PingUsage`, goes into `keepalive` (it is Cortex's `pingUsage`). The proxy's full `responseUsage` stays in `proxy` for real traffic. A proxy test pins the two equal on ping responses.
3. **Body copy.** A host may copy `Request.Body` into a `[]byte` that it wipes when the transport closes the request body. The transport can still read the body after `client.Do` returns, so reading the caller's slice directly would race with the core's wipe. A `string` copy stays forbidden.
4. **Proxy host API.** `proxy.Options.CheapModel` becomes host config (`*proxy.CheapModelConfig`). `proxy.NewDispatcher`, `(*Dispatcher).Pin` and `proxy.AuthHeader` are exported for `cmd/` tools.

## Review Focus

1. A detached summary that runs after its request ended still reaches the model (incoming ref still valid) — Task 4 test `TestIncomingRefOutlivesTheRequest`.
2. Gateway mode (`up.setKey != nil`): the incoming cheap model must carry the server key, never the caller's — Task 4 test `TestIncomingModelInGatewayModeUsesServerKey`.
3. A ping answered 4xx still stops the entry, and 5xx is retried: status now comes from `Response.Status` — Task 2 test `TestPingStatusComesFromResponse`.
4. After `Keeper.Shutdown`, the host holds no keep-alive credential — Task 3 test `TestShutdownReleasesEveryHeldRef`, Task 8 same for Cortex.
5. A redirecting upstream does not receive a second request carrying the key — covered for every host by `dispatchtest.Contract`.
