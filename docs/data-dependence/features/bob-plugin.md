It routes Bob with one block in the shell startup file and adds two hooks to Bob's settings. The hooks read only the session id, the event name and the `SessionStart` source. They never read the prompt, and they send nothing for events that carry model text. `status` and `doctor` read only the time of the newest Bob request from the dashboard. The status bar reads the newest Bob session id and its saved-token count, and that session's cache times, prefix size and context window. With a preset that prices Bob, it also reads the session's saved money and its unit name (`USD`, `Bobcoins` or `mixed`), which comes from the price configuration, not from customer data. All of these are counts, times, ids and that unit name. With the dashboard off, those reads find nothing: `status` and `doctor` cannot see Bob traffic, and the status bar shows `saved —` and `cache —`, never `saved 0`. Everything else still works. To list the cache strategies, `configure` runs the local proxy binary once to read its strategy table, with no network and no user data. `status` and `doctor` also read the tool deferral counts from `/stats` (numbers only). The default preset, `bob-ultrahigh`, **does depend on stored content**: it runs `ultrahigh`'s content components (`cache_aware_summarizer`, `extract_llm`, `extract_llm_sweep`, `extract` and the other cutters), which keep originals, summaries and held answers on the user's Mac so the model can get cut content back. The owner confirmed this change of the Bob default on 2026-11-11. What each keeps, and what it does at each level, is in its own row above; with less storage they cut less or not at all. Their summary calls send parts of the conversation that Bob already sent to Bob's own server only, with the user's own Bob key, and they use the user's Bob quota. Its tool deferral keeps tool names and counts (the `toolfilter` and *Tool deferral history* rows). Its price file (`prices.yaml`) holds only public rates, no customer data. The opt-in `lossless` preset keeps no customer data. The level changes nothing in the plugin itself. **Decided by:** Vitaly Zabershinsky, #973 (2026-11-11).
