To price a saving it must know which part of the conversation a rewrite changed and whether the provider had that part cached. It reads each request once and keeps only a hash and a size for each part, plus the cache breakpoints. The text is dropped as soon as it is hashed, and the hashes are held in memory, one set per conversation thread, plus each thread's last set for the sibling check (SharedWarm). So a restart does not lose them, it also saves them to one file beside the dashboard database (`<dashboard-db>.accountant-state.json`, readable by its owner only), every minute and when it stops, and loads them again when it starts. The file holds hashes, sizes, positions, and the ids and names the state needs (session and thread ids, tool and component names, model names, times). It holds no message text. It also holds one proxy version number, and it is ignored when that number differs or when it is more than one hour old. It is not written when there is no dashboard. It reads the tools and system sections the same way, as names, hashes and sizes, to report the envelope changes. On the OpenAI Responses wire it reads `instructions` as the system section and each `input` item as one part, with the same hash and size and nothing more. The result it writes to the dashboard is dollar amounts for each component, with their split by tier. Since #998 it also writes the same figures as token counts by tier (fresh input, cache read, 5-minute and 1-hour cache write), saved and caused: per component row, and per request for the keep-alive rescue, the cache split, the 1-hour head and the ended-change break. They are numbers only. `/api/stats` sums them in its `tokens` object. Since #1187 it also keeps the token count of each thinking block a model made, so that a block the client sends back is priced at its own count and not at a fixed price. From each response, JSON or stream, it reads the signature of each thinking block, the `data` string of each redacted thinking block, and the response's `thinking_tokens`. It keeps a 64-bit hash of each of those strings and a count, never the strings or any text. A response with no count, a count of 0, or more than 64 blocks is not kept. The table holds at most 20,000 blocks, the oldest go first, and one table serves all tenants: a key is the hash of a string that only the tenant who got it holds. It is saved in the same state file, and it is restored from a file up to 24 hours old, also when the rest of the state is too old or is refused. No level changes what it does.
