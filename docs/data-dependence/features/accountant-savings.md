To price a saving it must know which part of the conversation a rewrite changed and whether the provider had that part cached. It reads each request once and keeps only a hash and a size for each part, plus the cache breakpoints. The text is dropped as soon as it is hashed, and the hashes are held in memory, one set per conversation thread, plus each thread's last set for the sibling check (SharedWarm). So a restart does not lose them, it also saves them to one file beside the dashboard database (`<dashboard-db>.accountant-state.json`, readable by its owner only), every minute and when it stops, and loads them again when it starts. The file holds hashes, sizes, positions, and the ids and names the state needs (session and thread ids, tool and component names, model names, times). It holds no message text. It also holds one proxy version number, and it is ignored when that number differs or when it is more than one hour old, except for the thinking counts below. It is not written when there is no dashboard: with no dashboard the state stays in memory and is lost at a restart, and nothing else is stored. It reads the tools and system sections the same way, as names, hashes and sizes, to report the envelope changes. On the OpenAI Responses wire it reads `instructions` as the system section and each `input` item as one part, with the same hash and size and nothing more. The result it writes to the dashboard is dollar amounts for each component, with their split by tier. Since #998 it also writes the same figures as token counts by tier (fresh input, cache read, 5-minute and 1-hour cache write), saved and caused: per component row, and per request for the keep-alive rescue, the cache split, the 1-hour head and the ended-change break. They are numbers only. `/api/stats` sums them in its `tokens` object. Since #1187 it also keeps the token count of each thinking block a model made, so that a block the client sends back is priced at its own count and not at a fixed price. From each response, JSON or stream, it reads the signature of each thinking block, the `data` string of each redacted thinking block, and the response's `thinking_tokens`. It keeps a 64-bit hash of each of those strings and a count, never the strings or any text. A response with no count, a count of 0, or more than 64 blocks is not kept. The table holds at most 20,000 blocks, the oldest go first, and one table serves all tenants: a key is the hash of a string that only the tenant who got it holds. It is saved in the same state file, and it is restored from a file up to 24 hours old, also when the rest of the state is too old or the accountant library refuses it. A file with another proxy version gives back nothing. It is read only on the chat routes, from Anthropic responses. Since #1451 it runs on every request, with or without the dashboard, and it reads the same things in each case: sizes, hashes, token counts and, in memory for the length of one request, the request body it hashes. With no dashboard it stores nothing new on disk. It gives each request's Result to the metrics counters (`llm_savings_*`, which carry numbers only) and it has a per-request dollar figure (numbers only) for tool deferral's `/stats` ledger to read in #1445. The tool deferral ledger reads that figure. It also reads the thinking signatures of Anthropic responses with no dashboard, as hashes and counts in memory, so a thinking block that the client sends back is priced right. Since #1457 and #1460 a keep-alive ping books through a path that needs no dashboard. Since #1457 a single-tenant proxy pings without the dashboard too, and books through this same path. Only a hosted proxy with no dashboard sends no ping (the audit-sink rule). A manual ping (the Ping button) works like a scheduled one. For each ping that billed something, the proxy keeps the ping's facts in memory only, for the thread's next real request: the time of the ping, its window id and a few token counts and flags, at most 4096 threads, one entry per thread, never saved to disk. The next real request takes them and credits the rescue. A manual ping with no next request in the window books its spend only. Its estimated saving (`manual_saved_usd`) is no longer booked: a row written before #1460 keeps its estimate, and a row after it holds 0. The ping's spend goes to the metrics counters (`llm_savings_*`). These are numbers only. Since #1533 each request also stores its own token ratio, as three numbers: the bytes of the text it forwarded, the tokens the provider billed for it, and a flag that says the media price was cut to the bill. It stores two more byte counts beside the token counts it already had: the bytes the declaration filter removed, and the bytes the sweep's expands restored. Dashboard reads use them to turn removed bytes into the provider's tokens. They are counts. They hold no text, and no level stores more than these numbers. The thread's last two ratio numbers also stay in the in-memory store, with the other per-thread token counts, for the next turn's warm check. A row written before #1533 holds no such numbers, and its readers keep the old table. No level changes what it does.
