To keep the prompt cache warm, the proxy sends the exact same prompt again with the user's credential. Without the text, it cannot ping. The Ping button (`POST /api/me/cache/ping`) uses the same body and key. With keep-alive off, a request that carries the header `x-context-guru-ping: 1` is still held, for the button only: no ping is sent for it, and the body and key are released 300 seconds after the last request on a 5-minute cache, or 59 minutes after it on a 1-hour cache (a press does not extend it), and one account holds at most 16 such threads. Without the header nothing is held. The install adds the header and tells the user. An older install (from before `--no-ping-header`) gets it at its next session start, with the same notice. Any other install without the header is never changed. It gets a one-time note instead. The cache-state answer also carries the time of the next planned ping (a number, metadata), so the mod can hide the button while a ping fires before the cache expires. The manual holds also export counts and byte sizes to `/metrics` (holds evicted by bytes or count, too-large refusals, a body-size histogram, bytes held per tenant) and write one log line with sizes when a tenant holds 2 bodies of 8 MiB or more. These are metadata only and work at every storage level. **No dashboard, single-tenant (#1457):** the proxy still holds the thread and pings, under the account's cache strategy. The credential lives in process memory only. It is never written to the dashboard database, a store, capture storage, a state file, a log or a metric, and it is dropped when the hold ends or the process stops. No ping rows are written, because there is no dashboard. A ping's spend still goes to the metrics counters (`llm_savings_*`, numbers only). A hosted proxy with no dashboard holds nothing and pings nothing, as before: it keeps other people's credentials, so it needs an audit record first. A library host (Cortex, bifrost) is not affected: its own dispatcher resolves the credential. Decided by: David Amid, 2026-11-26 (#1457).
