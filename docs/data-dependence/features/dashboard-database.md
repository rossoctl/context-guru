The dashboard shows what Context Guru removed and what your setup carries. Every number on it needs only counts and prices. Every request row comes from traffic the proxy saw itself. On a local install the dashboard also reads two things from your disk, and stores neither: the working folder recorded in Claude Code's session files, to group folders into projects for the project picker, and each installed skill's description from its `SKILL.md`. The keep-alive calculator and recommendation (#868) replay the per-wait ping plan from columns the proxy already writes for each request: stop reason, wait cause, thread id, cache tier and provider. They read no text. The adapt and save-more replay (#1298) reads the same wait cause from each stored row to set its prefix floor. It is one short label and no text. Tool deferral's net-saving panel (#869) adds nine count and price columns per request: tokens deferred, the names list's tokens, searches, dropped searches, tools loaded, wrong guesses, and the gross, net and cost dollars. All three come from one figure: the accountant library's figure for the deferral. The net is that figure. It prices the definitions left out, the price-line change and the names list from the request bodies, and the search turns (the search output, the second pass over the loaded definitions, and their cache write on the next request) from token counts. The gross is its saved side, and the cost is gross less net. A request the library did not price (an unpriced model, a held estimate) books no dollars. The search-turn token counts are numbers from the response usage and our own token weights: no text. The tool inventory also records the built-in tools Claude Code defers (by name, with 0 tokens) and counts a tool loaded through search as a use. `save-more tools` reads the same inventory, the tool deferral history and the account's keep and always-defer lists. All of it is tool names, counts and prices, and works at the metadata level. Each request row also has one flag, `acc_priced` (context-guru#912), set when the accountant library priced the request. The keep-alive views read it to trust the library's stored rescue figure. It is a yes or no, with no text. Two more flags and two numbers sit beside it: `estimate_held` (a yes or no: the request's estimated figure was kept out of the totals), `estimated_saved_usd` (that figure, in dollars, the most it could be) and `estimated_saved_low_usd` (the least it could be). They hold no text. One more column, `acc_fallback` (#1004), holds a fixed code: why the accountant library could not price the request (`unpriced`, `unsupported_wire` and the like), or empty. The Overview counts these requests and leaves their cost out of the saving share. It holds no text. A request booked at $0 because the price list had not loaded is priced later from its own token counts and the model name, with no text (#920). Its compaction calls are priced the same way, from their model name and token counts, which the proxy keeps in memory and does not store (#1033). Each request row also keeps the unit of its costs, `currency` (`USD`, or a name the price file gives, such as `Bobcoins`): it is configuration from the price file, not user data. An earlier history import copied whole request rows from those session files; it is removed, and its rows are deleted when the database opens.

The cache state (`/api/cachestate`) and the manual ping estimate the size of a session's next request. They take the median of the `fresh_input` plus `cache_write` token counts of the model's last `NextInputWindow` billed requests in the session. It is a count from the stored rows. No text is read.
